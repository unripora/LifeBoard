# 02 · 运行时：生命周期、租约与无状态

> 权威来源：`PluginLifecycle.kt`、`PluginRuntimeManager.kt`、`JsPluginLoader.kt`

## 一、三档生命周期

| 声明 | 何时加载 | 普通释放条件 | 典型 |
|---|---|---|---|
| `onDemand`（默认） | 首次业务调用 | 最后一个使用者离开后空闲 300 秒（可配） | 定时/手动同步 |
| `sessionScoped` | 首次业务调用 | 最后一个使用者离开后**立即**停机 | 详情页型 |
| `resident` | 可信目录就绪后预热（需获准名额） | 仅无活跃使用者时可因名额/预算降级 | 需要常驻 |

**声明 ≠ 实际**：`resident` 还要看常驻名额（默认 2）、全局预算和回收总开关。
被降级时宿主会给出原因，界面应展示——否则用户不理解"为什么声明了常驻还被回收"。

## 二、无状态三规则（硬要求）

> 插件**随时可能被卸载**。以下三条不是建议，是正确性前提。

### 规则 1：模块级变量只是缓存

```js
let cachedToken = '';   // 可以被丢弃，重建后必须能从持久层恢复
```

- 模块变量、闭包、`Map` 里的东西在运行时重建后**全部消失**
- 不要假设"宿主不会卸载我"——按需加载下这是常态

### 规则 2：跨调用状态必须落到持久层

| 数据 | 去处 |
|---|---|
| 无秘密的状态、游标、设备号 | `ctx.files` |
| **秘密**（令牌、cookie、密码材料） | `ctx.credentials`（加密） |

**不要把秘密写进 `ctx.files`**：那是明文目录。小米健康把会话 cookie 存进
凭据槽而不是文件，正是因为 cookie 等价于密码。

### 规则 3：分页状态编码在游标里

- 不要依赖"上一次调用留下的页码变量"
- 每页请求都应能从游标自身推导出下一步，否则被卸载后翻页就断了

## 三、什么时候保存状态

**在业务过程中保存，不要等卸载钩子**：

```js
// ✅ 正确：阶段一变就落盘
pendingLogin.stage = 'captcha';
savePendingLoginSnapshot();

// ❌ 错误：只在 onUnload 里保存
export function onUnload() { saveEverything(); }
```

原因：宿主明确 `onUnload` 是**尽力调用、不保证执行**。进程被杀、脚本中断、
运行时故障都不会触发它。钩子只适合做清理与日志。

## 四、`onUnload` 钩子

```js
export function onUnload(options) { /* 尽力清理 */ }
```

| 项 | 规则 |
|---|---|
| 调用时机 | 空闲释放、会话结束、包更新、进程退出 |
| **不调用** | 撤销信任、清除数据、故障中断（继续执行插件代码本身就是错的） |
| 超时 | 1 秒同步预算 + 最多 2 秒总等待，超时请求中断后继续回收 |
| 可用能力 | `ctx.log` |
| **不可用** | `ctx.files`、`ctx.credentials`（加载期未绑定上下文，调用会抛错） |

**为什么钩子不允许写文件**：允许写入却保证不了超时，关闭流程会被阻塞 I/O 拖死。
当前实现选择"根本不允许写"，这是权衡后的保守方案，不是遗漏。

## 五、限额

限额分两类，**性质不同**：

### 协议固定语义（不随宿主调整）

| 项 | 值 | 超限行为 |
|---|---|---|
| 包解压总字节 | 16 MiB | 拒载 |
| 包条目数 | 512 | 拒载 |
| 机器字段（id / actionId / payload） | 4 KiB | **丢弃该节点/交互**，不截断 |
| 展示文本 | 64 KiB | 按字符边界截断并告警 |
| 代码正文 | 256 KiB | 截断 |

**机器字段为什么不能截断**：截断后的 id 会指向一个不存在的目标，
比直接丢弃更难排查。展示文本截断只是少显示几个字，语义不坏。

### 宿主默认策略（可按端调整）

| 项 | 默认 | 说明 |
|---|---|---|
| 单段同步执行预算 | 1 秒 | 纯同步死循环会被中断 |
| 无进展等待 | 60 秒 | 等宿主回调；有实质推进就刷新 |
| HTTP 响应体 | 4 MiB | 有界读取，超限中止 |
| WebSocket 单帧 | 4 MiB | 超限丢弃并关闭连接 |
| 空闲阈值 | 300 秒 | `onDemand`，可配 `[60, 3600]` |
| 常驻名额 | 2 | 超出按 LRU 降级空闲者 |
| 连续同步超限停用 | 3 次 | 停用后需显式启用或升级 |

## 六、故障与停用

- 单段同步超限 → 中断本次调用，返回失败（**不**伪装成"没有数据"）
- 连续 3 次 → 停用该插件：回收运行时、从列表移除
- 停用**跨重扫保留**：切页签或重扫都不会让它复活
- 恢复：用户显式启用，或安装新版本
